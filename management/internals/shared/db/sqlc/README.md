# sqlc overlay

Prototype of the data layer without gorm: SQL in `queries/`, Go generated by
sqlc into `gen/`, one repository per table on top, running unchanged on
Postgres and SQLite.

- `sqlc.yaml` points sqlc at the goose migration files of the store, so a
  query that names a column the migrations do not create fails `go generate`,
  not a deployment. Overrides declare which nullable columns never hold NULL
  and map JSON text columns to `sqltypes`.
- `queries/*.sql` is written once in the portable subset both engines accept,
  with Postgres placeholders. `querier.go` binds the generated code to the
  handle gorm uses (pool or transaction) and, on SQLite, rewrites `$N` to `?N`
  and drops the row lock clause.
- `setupkeys.go` shows the repository shape: shared `db.Conn`, `WithTx`, lock
  strength per read, generated rows mapped to the domain type.
- `setupkeys_test.go` runs the repository on SQLite and, with
  `NETBIRD_STORE_ENGINE=postgres`, on Postgres, and checks that the gorm store
  reads what the generated queries wrote.

Regenerate with `go generate ./management/internals/shared/db/sqlc/`.
