# 30 Generated code, OpenAPI, protobuf, dependencies

Generated files are outputs. The review question is never "is this generated
code right" but "was the source changed, was the right generator run, and is
the wire contract still compatible". Line references are to OSS `main` at the
time of writing; re-check them when a rule looks stale.

## Rules: any generated file

### GEN-001 Source and output change together
severity: blocker
scope: pairs in the inventory
check: `openapi.yml` changed without `types.gen.go` (or the reverse); a
`.proto` changed without its `.pb.go` (and `daemon.pb.gw.go` for the daemon);
an interface with a `_mock.go` sibling changed without the mock; a Go service
under `client/ui` changed without the bindings regenerated in CI passing.
say: "Run `<generate.sh | go generate ./pkg | mage openapi:generateV1Bindings>`
and commit the output; CI <does / does not> catch this, so the reviewer has to."

### GEN-002 Only the intended bodies change, never the generator header
severity: blocker
scope: `**/*.pb.go`, `**/*.gen.go`, `**/*_mock.go`
check: the first 20 lines of a modified generated file differ from base
(`protoc`, `protoc-gen-go`, `protoc-gen-go-grpc`, `oapi-codegen ... version`,
`Generated by this command:`). A regeneration that rewrites every file in a
directory while the `.proto` diff is one field.
say: "`proto-version-check.yml` fails on header changes. Regenerate with the
versions in the file's own header (they differ from some `generate.sh` pins:
`protoc` is unpinned and the grpc plugin pin has drifted for `flow`). Do not
fix the pins in a feature PR."

### GEN-003 Hand edits to generated files are rejected
severity: blocker
scope: inventory, plus `bundle.yaml`, `proxy/web/dist/`, non-English locale
files, cloud `config/crd` and `config/rbac`
check: a diff hunk in a generated file whose change is not explained by the
source diff (a renamed field, a removed method, a formatting change).

### GEN-004 Activity codes are append-only and unique
severity: blocker
scope: `management/server/activity/codes.go`
check: a new constant reusing a value; an existing value changed; a code
inserted mid-sequence that shifts iota. The CI grep fails on duplicates;
renumbering corrupts stored events silently. Every new code also needs its
entry in the code-to-message map in the same file.

## Rules: OpenAPI (`shared/management/http/api/openapi.yml`)

### API-001 `required` decides the Go type; changing it is a break
severity: blocker on existing schemas, should on new ones
scope: `openapi.yml`
check: a field added to or removed from `required` on an existing schema
(optional becomes `*T` with `omitempty`; required becomes a value), or an
`operationId` added or renamed on an existing operation (renames the
generated `*JSONRequestBody`/`*Params` types). Consumers:
`shared/management/client/rest`, `terraform-provider-netbird`, netbird-cloud
`integrations/` (dozens of import sites).
say: "This changes the generated Go type for `<schema>`; every consumer of
`api.<Type>` breaks. Add a new field instead, or coordinate the break."

### API-002 Response schemas list every always-populated field as required
severity: should
scope: new or changed response schemas
check: a response property the handler always fills that is not in
`required` (it generates a pointer and every consumer nil-checks it);
a request property marked required that the handler treats as optional.

### API-003 Every property has `description` and `example`; typed formats
severity: should
scope: new properties
check: a property without `description` or (for scalars) `example`;
a timestamp not `type: string, format: date-time` with an RFC 3339 UTC
example; an ID not `type: string` with an xid-style example; an integer
without `format: int64` where size matters; validation expressed in prose
rather than `minimum`/`maximum`/`enum`/`pattern`.
why: `update-docs.yml` regenerates the public API pages from the spec on
release tags; the spec is the documentation.

### API-004 Operation shape
severity: should
scope: new operations
check: missing `summary` in "Verb a Thing" form (List / Retrieve / Create /
Update / Delete), missing `description`, missing `tags`, path params not
`in: path, required: true, schema: {type: string}` with a description, and
missing `$ref`s to the standard responses `bad_request`,
`requires_authentication`, `forbidden`, `internal_error` (plus `not_found`,
`conflict`, `validation_failed` where applicable). Delete returns `'200'`
with empty content.

### API-005 Paths and params
severity: should
scope: new paths
check: path not under `/api/`, collection not plural kebab-case
(`/api/setup-keys`), item param not `{<resource>Id}` lowerCamel
(`{peerId}`); a kebab-case param (`{peer-id}` exists once and is the outlier,
not the pattern). Cloud integrations use `/api/integrations/<area>` with `{id}`.

### API-006 Tags are declared, and cloud-only or experimental is marked
severity: should
scope: `tags:` usage
check: an operation tag not present in the top-level `tags:` list with a
description; a cloud-only endpoint whose tag or operation lacks
`x-cloud-only: true`; an unstable endpoint without `x-experimental: true`.
Known undeclared tags today (`Agent Network`, `Networks`, `Self-Hosted
Proxies`, `Geo Locations`) are fixed when touched, not re-flagged.

### API-007 Schema naming and composition
severity: nit
scope: new schemas
check: write body not `XRequest`; response not the bare `X`; embeddable
subset not `XMinimum`; full form not `allOf: [$ref XMinimum, {...}]`; a
property re-declared that the `allOf` base already has; a repeated inline
enum instead of a named enum schema (inline enums generate per-parent types);
polymorphism without `oneOf` + `discriminator`.

### API-008 `nullable` does not mean optional
severity: nit
scope: `openapi.yml`
check: `nullable: true` added to express "may be absent" (the spec is 3.1 but
uses the 3.0 keyword; the generator emits the same `*T` either way). Leave
the field out of `required` and document null semantics in `description`.

### API-009 Deprecate, never remove
severity: blocker
scope: existing paths, params, properties
check: a path, parameter, property, or enum value removed or renamed.
say: "Mark it `deprecated: true` with the replacement in the description; API
users and the Terraform provider depend on it."

### API-010 Pagination envelope and query semantics
severity: should
scope: list endpoints with `page`/`page_size`
check: envelope not `{data[], page, page_size, total_records, total_pages}`
all required; `page` without `minimum: 1`; `page_size` without a default and
a maximum; handler that serialises an empty page as `null` instead of `[]`;
paged SQL without a deterministic `ORDER BY` tie-breaker; page 1 not offset 0.

### API-011 A new endpoint touches the fixed set of places
severity: should
scope: new operations
check: missing any of: schema + path in `openapi.yml`; regenerated
`types.gen.go`; domain conversion (`ToAPIResponse` / `FromAPIRequest` on the
domain type); handler registered through the area's `AddEndpoints` in
`management/server/http/handler.go`; REST client method and test in
`shared/management/client/rest/<area>.go`; docs PR URL in the body.
Cloud-only endpoints: spec in OSS under an `x-cloud-only` tag, implementation
in netbird-cloud, OSS PR merged first.

### API-012 `apiv1alpha1` is its own pipeline
severity: should
scope: `shared/management/http/apiv1alpha1/**`
check: `openapi.yaml` or a split file changed without regenerated
`bundle.yaml` and `types.gen.go` (no CI check); `bundle.yaml` is embedded and
drives the request-validating middleware, so a stale bundle rejects valid
requests at runtime.

## Rules: protobuf

### PB-001 Additive only; reserve what you remove
severity: blocker
scope: `**/*.proto`
check: a field removed, renumbered, retyped, or renamed; an enum value
removed or renumbered; a message or RPC removed; a numbering gap without
`reserved N`. `buf breaking` fails the first set; the reviewer catches gaps
(signal `Body.Type` skips 3 without reserving it, do not add another).
say: "Old agents must keep working against new management: add the field,
`reserved` the old number, and keep populating the old field for ungated
peers."

### PB-002 Deprecate in place with the replacement named
severity: should
scope: `**/*.proto`
check: a field superseded without `[deprecated = true]` and a comment naming
the replacement (pattern: `PeerIP = 1 [deprecated = true]` "Use
sourcePrefixes instead"); a whole message without `option deprecated = true`.

### PB-003 Field style follows the surrounding message
severity: nit
scope: `**/*.proto`
check: a new field in a snake_case message written camelCase or vice versa
(legacy messages are camelCase, newer component messages snake_case); never
rename an existing field (its Go name is public API).

### PB-004 Unset must be distinguishable when it matters
severity: should
scope: `**/*.proto`
check: a scalar whose zero value is a valid setting (port 0, false, empty
string) added without proto3 `optional` or a wrapper message, so the server
cannot tell "not sent by an old client" from "set to zero"; a tri-state
encoded as two bools instead of an enum or message.

### PB-005 Enums have an unknown zero and callers handle unknown values
severity: should
scope: `**/*.proto`, code switching on a proto enum
check: a new enum whose `0` is a meaningful value (new enums use
`XUnknown = 0`); a `switch` on an enum with no `default` (old peers receive
numeric values they do not know).

### PB-006 Wire names are contract
severity: blocker
scope: `package`, `service`, `rpc` names, `go_package`
check: a change to a gRPC package or service name (clients dial the FQN);
netbird-cloud pins `management.ProxyManagerService` with a test.

### PB-007 Management and Signal proto changes are discussed first
severity: ask
scope: `shared/management/proto/**`, `shared/signal/proto/**`
check: any change without a linked issue. Daemon proto contributions are
welcome but still additive.

## Rules: version gating (old agent, new management)

### COMPAT-001 New server-to-client behaviour is gated
severity: blocker
scope: anything that changes what `SyncResponse`, `NetworkMap`, or the
network-map components contain; `management/internals/shared/grpc/**`,
`management/internals/controllers/network_map/**`,
`shared/management/types/**`, `legacynmap/**`
check: new shape sent without one of: a `PeerCapability` value checked with
`peer.HasCapability`; a `version.MeetsMinVersion(<namedConst>, peer.Meta.WtVersion)`
gate with the `IsDevelopmentVersion` bypass; or the sync-message version
negotiation (`HighestCommonSyncMessageVersion`). The legacy field must still
be filled when the gate is off.
say: "What does a 0.5x client receive here? Gate on `<mechanism>` and keep
`<legacy field>` populated; add a test for the old-peer shape."
Existing gates to pattern-match: `remoteJobsMinVer`,
`firewallRuleMinPortRangesVer`, `firewallRuleMinNativeSSHVer`,
`DnsForwarderPortMinVersion`, `deprecatedRemotePeersVersion`,
`minSessionCodeVersion`.

### COMPAT-002 Gate values are named constants, duplicated nowhere new
severity: should
scope: as above
check: an inline version string in a comparison; a min-version constant
copied into a second package (the firewall-rule constants already exist in
two places; do not add a third).

### COMPAT-003 Account-wide derived values use the lowest common denominator
severity: should
scope: account-level settings derived from peer versions (DNS forwarder
port and similar)
check: a derived value computed from the newest peer or the account default
when older peers in the account cannot honour it.

### COMPAT-004 New capabilities are new enum values, advertised and checked
severity: should
scope: `PeerCapability`, `peerCapabilities` in `shared/management/client/grpc.go`
check: a capability reused for a second feature; a capability added to the
enum but not advertised by the client, or advertised but never checked
server-side.

### COMPAT-005 The client tolerates an old management, the UI tolerates an old daemon
severity: should
scope: `client/**` consuming a new proto field; `client/ui/**`, `client/cmd/**`
consuming new daemon RPC fields
check: a client path that assumes a new field is present (nil or zero-value
deref) rather than defaulting safely; a UI or CLI feature with no behaviour
when the daemon does not know the RPC (`Unimplemented`).

## Rules: dependencies and modules

### DEP-001 No new `replace` in OSS `go.mod`; forks live under their own path
severity: blocker
scope: `/go.mod`
check: an added `replace`. Existing ones (`circl`, `easyjson`, `wails`) may be
bumped; a bump commit links the fork commits.
say: "`no-new-replace.yml` fails. Fork into `github.com/netbirdio/<name>` and
require it directly, as `netbirdio/ice`, `netbirdio/go-nat`,
`netbirdio/wireguard-go` do."

### DEP-002 Dependency changes are their own PR and the user's decision
severity: ask
scope: `go.mod` require lines
check: a require added, removed, or bumped in a PR whose purpose is something
else. Dependabot groups (`golang.org/x`, aws-sdk, pion, gorm, otel,
testcontainers, wireguard) are the sanctioned bump path.

### DEP-003 Licence boundary
severity: blocker
scope: `go.mod`, imports
check: a new module with a GPL-family licence reachable from BSD packages;
a BSD package importing `management|signal|relay|proxy`
(`check-license-dependencies.yml`).

### DEP-004 `go mod tidy` clean, `vendor/` never committed, no stray `go.sum` in proto dirs
severity: blocker
scope: `go.mod`, `go.sum`, `vendor/`
check: tidy leaves a diff; a `vendor/` directory; a new `go.sum` outside a
module root (two stray ones exist under the proto dirs; do not add more).

### DEP-005 Tool directives, not `go install` at generate time, for mocks
severity: nit
scope: `go.mod` `tool` block, `//go:generate` lines
check: a new `//go:generate` that `go install`s a tool version instead of
using the `go tool` directive (`mockgen`, `chglog` are in the `tool` block).
